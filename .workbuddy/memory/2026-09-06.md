## 环境踩坑（重要，跨项目可复用）

1. **WorkBuddy broker 沙箱会拦截 node 子进程的 rename/mkdir**（node-brokered-fs-shim，CODEBUDDY_BROKER_DENY）：
   - `npm install` 卡死在 bin link 阶段（几十分钟无进展即此因），错误 `rename node_modules/.bin/jiti -> .jiti-xxx`。
   - Next dev server 无法 `mkdir .next`（写 /tmp 也被拒），500。
   - 对策：**重活（npm install / next dev）让用户在自己的终端跑**；agent 侧只做代码验证（tsc --noEmit、纯函数 node 测试）。
   - `~/.workbuddy/settings.json` 的 `sandbox.extraAllowWrite` 加入项目路径后，shell 命令可写项目目录，但 node 子进程 shim 不一定生效（本次未生效）。
2. **网络极慢**（~65KB/s）：npm 全量安装 30+ 分钟不可行；改用「缓存已有 + 手动 ln -s 重建 .bin」让 tsc/next 可执行。
3. next 包解压残缺（缺 index.d.ts/types/）→ dlopen 原生 swc 报 `code signature invalid (errno=85)` → Next 回退下载 wasm。残留问题，用户本地 npm install 重装即愈。
4. 用户终端跑法：`npm install && npm run dev`（.env.local 已建占位，填 LLM_API_KEY / LLM_BASE_URL / LLM_MODEL）。
